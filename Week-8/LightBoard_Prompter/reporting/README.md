## What changed

Each feed check uses a bounded per-boot/per-request URL parameter and Cache-Control:no-cache,max-age=0. Responses log Age when present. TLS/allowlisted hosts, double candidate comparison, full download hash/size checks, partition limits and boot health remain. This requests freshness; CDN or network behavior still needs live measurement, and instant delivery is not guaranteed.

After a verified download and before choosing the boot partition, the board stores an installation receipt. After healthy SDK VALID boot it reads exactly those running-image bytes back from flash and verifies the full published SHA. A USB boot without that matching receipt cannot claim an OTA installation. It signs version/foundation/SHA/size/healthy/OTA-state/timestamp/nonce with the provisioned key and posts over verified HTTPS. Only Google's ContentService redirect is accepted, as GET, without replaying the POST. Failures retry reporting only, never a model request or firmware installation. Reports recur every10minutes after success.

Receiver rejects bad signatures, wrong board IDs, invalid fields, stale timestamps and unhealthy/pending boots. Replayed events cannot refresh timestamps or overwrite newer reports. Only the latest report is stored. The private reader polls at most once/minute. It stores exact-image acknowledgments separately from immutable intake/publication/rejection history. A reporting outage keeps Published · awaiting board; it does not cause another generation. Installed means that image passed boot health, not an aesthetic assessment or a promise the board remains powered forever.

GitHub's green build still means build/publication succeeded. Its summary explicitly says installation awaits board confirmation. The private page and inspectEmailProcessing expose the authenticated installed status. Historical receipts keep their original false deviceConfirmed fields; new separate installation evidence is authoritative.
